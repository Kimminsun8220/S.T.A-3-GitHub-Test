# Auto Career Brief 구현 기준

사용자가 2026-09-15 제공한 PRD를 구현용으로 정리한 문서입니다.

## 목적

자동차·모빌리티 산업의 사업·상품기획 취업 준비를 위해 산업 변화 → 직무 관점 분석 → 내 생각 → 면접·자소서·포트폴리오 활용으로 이어지는 개인 자료 보관소를 만듭니다. 완성차를 우선하며 사업기획과 상품기획을 함께 탐색합니다.

## 분류

- 시장: 판매량, 점유율, 경쟁사, 중국 브랜드, 전기차·하이브리드, 소비자 변화
- 고객·상품: 고객 니즈, VOC(고객 의견), 만족도, 신차, 가격·옵션, USP(차별적 강점), 포지셔닝, 개선 사례
- 사업·BM: 신규 사업, 구독, 멤버십, 서비스, 플랫폼, BM(수익을 만드는 사업 구조), 운영
- 직무·채용: JD(업무와 자격을 설명한 채용 내용), 역량, 활용 데이터, KPI(성과를 판단하는 핵심 지표), 협업 부서

## P0

산업 검색과 직무 검색을 각각 지원하고 최근 자료를 분류합니다. 3줄 요약, 무엇이 달라졌는가, 사업기획 관점, 상품기획 관점, 확인할 데이터/KPI, 취업 활용도, 생각해볼 질문과 작은 Action(직접 해볼 일)을 정리합니다. Notion DB에 저장하고 중요한 최대 3건을 Slack으로 전송합니다.

Notion 필드: Title, Date(발행일), Collected Date(수집일), Category, Company, Summary, Job Insight, KPI, Career Use, My Thought, Action, URL. My Thought는 AI가 채우지 않습니다. 질문은 별도 본문에 둡니다. 원문 사실과 AI 제안을 구분합니다.

Slack에는 제목, 3줄 요약, 기획자 관점, 확인할 데이터, 생각해볼 질문, Action, 원문/Notion 링크를 담습니다. 최신성·직무 관련성·취업 활용도를 기준으로 최대 3건을 선정합니다.

## 이후 추가

경험 자동 연결, 타 산업 BM 자동 추천, 예상 면접 질문 생성, JD 역량 분석, Weekly Report. 타 산업 사례 적용과 내 경험 연결은 최종 학습 목표이며 해당 자동 기능은 P0 완료 조건에 포함하지 않습니다.

## 개발과 완료 기준

feature/news-search → feature/career-insight → feature/notion-save → feature/slack-digest 순서로 기능을 나눕니다. 각 기능은 별도 Branch 생성 → 개발 → commit → push → Pull Request → 확인 → main merge 순서입니다.

현재 첫 기능의 완료 기준은 산업/직무 두 검색 경로 실행, 원문·날짜 확인, 분류·요약 목록 저장, 중복·날짜·새 버전 저장 검사, GitHub 변경 검토입니다. 외부 연결은 후속 기능입니다. 뉴스 검색은 Codex 웹 도구가 수행하며 예약 실행은 이번 범위가 아닙니다.

프로젝트 성공은 기사 수가 아니라 산업 변화와 사업/상품기획의 의미, 확인할 데이터와 본인 생각을 설명할 수 있는가로 판단합니다.

## 커리어 인사이트 기능

수집 결과를 원본으로 유지하고 Codex가 자료별 분석을 별도 JSON으로 작성합니다. 분석에는 무엇이 달라졌는가, 사업기획 관점, 상품기획 관점, 확인할 데이터/KPI의 뜻·필요성·입수처·접근 가능성, 취업 활용, 학습 질문, 작은 실습과 한계가 포함됩니다. 원문의 사실 요약 번호와 분석을 연결하고 My Thought는 빈칸으로 유지합니다.

Python 도구는 AI를 호출하는 프로그램이 아니라 분석의 형식·원문 연결을 검사하고 새 버전 JSON/Markdown으로 저장하는 역할입니다. 수집 JSON의 내용 지문을 함께 기록하며 기존 원본·결과는 덮어쓰지 않습니다. Notion 저장과 Slack 전송은 후속 기능입니다.

기간 기준: 발행일 기준 당일 포함 7일은 최신, 8~30일째는 부족할 때만 추가하는 보충, 30일 초과 직무 자료는 참고로 구분합니다. 발행일 미확인은 별도 표시합니다.
