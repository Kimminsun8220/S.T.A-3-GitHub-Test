# Notion 발행과 Slack 요약

사용자가 요청한 서비스와 작업 범위에만 적용한다. 기존 파일·전송 기록과 원격 내용을 먼저 읽는다. 채널·데이터소스·메시지 ID 등 개인 연결 정보는 Git에서 제외된 프로젝트 output의 전송 기록 또는 작업일지에서 찾고, 서비스에서 현재 존재와 접근 가능 여부를 확인한다. 대상을 확인할 수 없으면 목적지를 한 가지 질문으로 확인한다.

## Notion 기사와 발행 목록

- Notion에는 사용자가 읽을 최종 선정 기사만 정리한다. 제외 후보·보류 목록·제외 사유는 로컬 output에만 보관하고 회차 요약에 싣지 않는다. 재선정으로 이번 회차에서 빠진 기사가 이미 게시되어 있으면 본문·속성을 로컬에 백업한 뒤 해당 회차 링크와 불필요한 기사 페이지를 휴지통으로 옮겨 정리한다. 단순히 제목에 '제외'를 붙여 기사 표에 남기지 않는다. 다른 회차에서 유효하게 사용 중인 기사나 사용자 작성 기록이 있는 페이지는 보존하고 이번 회차 연결만 제거한다.

- 첫 표에는 Title·뉴스 태그·Date·짧은 Summary·Company·Career Use를 표시한다. Summary는 기사 상세를 한눈에 이해할 1~2문장으로 줄인다. Source와 원문 URL은 상세에서 확인할 수 있게 둔다.
- 삭제한 Freshness·선정 결과·뉴스 검수·선정 이유 열은 다시 만들지 않는다. 기간 구분·선정 근거는 로컬 수집 기록과 발행 요약에 남긴다. 검증 상태·실습 결과·실습 링크는 사용자의 실습 기록이므로 유지한다.
- 전체 기사 보기에는 날짜 필터를 두지 않는다. 보충 기사도 실제 조회되는지 확인한다. 주간 보기가 따로 있으면 이름으로 구분한다. 필터 변경 성공 응답만 믿지 말고 반환된 설정과 보기의 기사 목록을 확인한다.

- 기사 본문은 easy-reading.md의 실무 해석 형식을 따른다. Job Insight 속성도 같은 해석으로 맞추고 AI 해석임을 표시한다. 본문 실습과 Action 속성도 일치시킨다.
- 기사 데이터베이스와 발행일별 요약집 모음을 구분한다. 현재 사용자의 발행 목록은 '대표뉴스 모음'이며, 정확한 대상은 기존 전송 기록과 실제 데이터소스로 확인한다. 기사 상세는 기존 기사 DB에, 회차별 요약은 발행 목록의 행 아래에 저장한다.
- 저장 전에 실제 속성 이름·형식과 해당 발행일의 기존 행을 확인한다. 같은 회차 행이 있으면 재사용하고 연결된 요약부터 읽는다. 여러 후보가 있으면 임의로 새 행을 만들거나 합치지 않는다. 발행일은 자료의 수집 기간과 구분한다.
- 새 회차일 때만 발행일·제목을 가진 행을 만들고 그 행 아래 요약 페이지를 생성한 뒤 '페이지 링크'에 주소를 저장한다. 개인 최상위에 회차 요약을 만들지 않는다. 기존 발행일 속성 형식과 최신 발행일 우선 정렬을 보존한다.
- 요약에는 선정 기사 상세 링크와 선정 이유·기간·확인 한계를 담는다. Slack에도 이 요약집 주소를 사용한다.
- 기존 수정은 본문·속성을 output에 새 버전으로 백업한 뒤 필요한 부분만 변경한다. My Thought, 내 생각 본문, 실습 결과·링크·상태, 기사 사실·날짜·출처와 기존 페이지 관계를 보존한다. AI가 사용자 생각을 채우거나 기존 입력을 빈칸으로 초기화하지 않는다.
- 본문 변경과 속성 변경은 각각 실행·확인한다. 저장 후 기사, 발행 행, 요약 링크를 재조회해 성공한 부분을 기록한다. 일부 실패나 시간 초과가 있으면 현재 상태를 확인하고 실패한 부분만 재시도한다.

## Slack 브리프

- 기본 발신자는 Slack 봇이다. [봇 발송과 중복 방지](bot-delivery.md)를 읽고 전용 스크립트를 사용한다. 기존 개인 명의 메시지는 자동 삭제하지 않는다.

- 승인된 채널에 기존 구성(메인 안내와 기사 댓글)이 있으면 그 구성을 따른다. 대표 기사 최대 3건을 요약하고, 실습은 기본적으로 Notion에서 읽도록 한다.
- 기사별 핵심 사실 요약 → 사업기획 관점 → 상품기획 관점 → 확인할 데이터 → 생각해볼 질문 → 원문·Notion 상세 링크 순서로 쓴다. 메인 안내에는 전체 요약집 링크를 둔다.
- 두 직무 관점은 Notion의 동일 기사 해석을 각각 1~2문장으로 줄인다. 핵심 의미와 이유·조건을 남기며 질문만으로 대체하지 않는다. Notion에 없는 사실·기업 의도·성과를 덧붙이지 않는다. 판단 근거가 길면 상세 링크로 연결한다.
- '기사에 기반한 AI의 실무 해석'임을 표시한다. 실제 발언은 확인된 출처가 있을 때만 인용한다. 독자의 생각을 묻는 질문은 별도 영역에 둔다.
- 기존 메시지 수정 요청이면 채널·메시지 ID와 댓글을 읽고 기존 메시지를 편집한다. 새 메시지로 중복 전송하지 않는다. 작성자가 달라 편집할 수 없으면 권한 제한을 알린다.
- 메시지마다 성공 여부와 ID를 로컬 전송 기록에 저장한다. 재조회로 해석·질문·링크 보존과 부분별 반영을 확인한다. Notion 수정 요청만으로 이미 발송된 Slack까지 수정하지 않는다.

## 완료 보고

본문·속성·발행 목록·Slack 각각 실제 수행한 결과와 확인 범위를 구분한다. 전송 규칙을 추가한 것, 실제 1회 전송, 예약 자동 실행 설정은 서로 다른 완료 상태다.
