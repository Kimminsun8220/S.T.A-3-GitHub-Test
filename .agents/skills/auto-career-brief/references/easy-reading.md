# 쉬운 뉴스레터 작성 기준

planning-validation.md는 내부 검토 참고로만 사용한다. 최종 뉴스레터에는 쉬운 분석만 싣고 심화 분석은 접기 영역까지 포함해 없앤다. 이 문서의 표시 순서를 우선한다.

## 바로 읽는 기사 분석

- 기획 직무를 처음 준비하는 대학생이 이해할 수 있는 존댓말로 작성한다. 문장 하나에 핵심 하나를 담는다.
- 무슨 일이 있었나 → 왜 중요한가 → 사업기획 관점 → 상품기획 관점 → 어떤 데이터를 볼까 → 취업 활용 → 내가 해볼 것 → 내 생각을 위한 질문 순서로 읽힌다.
- 각 직무 관점은 2~3문장으로 핵심 해석, 중요한 이유, 판단에 필요한 근거를 연결한다. 사업기획은 고객 확보·매출·비용·이익·사업 운영의 의미를, 상품기획은 고객의 이용 환경·선택 이유·상품 구성·지원 서비스의 의미를 기사에 맞게 설명한다. '보겠습니다/물어보겠습니다'라는 행동 선언이나 질문만으로 끝내지 않는다.
- 원문 사실에서 해석으로 이어지는 이유를 밝히고 확인되지 않은 의도·효과는 가능성 또는 가설로 쓴다. 실제 현업자 발언은 출처가 있는 경우에만 인용하며, AI의 실무 해석과 구분한다. 데이터는 핵심 2개만 쉬운 뜻과 알고 싶은 점으로 설명한다. 독자 질문은 easy_read.question, 실습은 easy_read.action에 둔다.
- 공통 '3분 요약' 제목과 매번 같은 안내 문구를 넣지 않는다. '무슨 일이 있었나?'부터 바로 시작한다. '기여이익', '반증' 등 상세 검증 설명은 출력하지 않는다. 필요한 전문용어는 사용한 자리에서 풀어 쓴다.
- 기업 의도·성과가 확인되지 않았다는 핵심 한계는 쉬운 요약에도 짧게 남긴다. 쉽게 쓰려고 불확실성을 없애거나 혜택을 과장하지 않는다.
- 실습은 정확히 두 개다. '✅ 가볍게 완료'는 3~5분 안에 추가 검색 없이 끝낼 수 있는 작은 작업 하나, '🚀 도전해보기'는 20~40분 정도로 비교·조사·기획 결과물 하나를 만들도록 제안한다. 각각 예상 시간과 완료 기준을 적는다. 도전 과제를 여러 과제 묶음으로 늘리지 않는다. 사용자의 결과·생각·상태는 보존한다.

## 입력과 표시

schema_version 2의 각 분석 행에 `easy_read` 객체를 추가한다. 필드는 happened, importance, business, product, data, action, career, question의 8개 문자열이다. 전체 최대 1800자, 권장 900~1400자. 이 필드가 없는 과거 입력은 재현 목적으로 계속 지원하며 새 뉴스레터에는 반드시 넣는다.

easy_read.action 문자열에는 가볍게 완료/도전해보기 두 작업을 담는다. planning.py는 쉬운 분석만 출력한다. 기존 상세 분석은 원본 JSON·로컬 백업에서 보존하며 뉴스레터에 재삽입하지 않는다. '내 생각', 실습 기록과 원문 출처는 계속 유지한다.

Notion·Slack 저장 또는 수정 시에는 [발행 지침](delivery.md)을 따른다. 기존 본문·속성을 새 파일에 백업하고 요청한 부분만 수정한다. 사용자 입력은 보존하며 Summary는 짧은 한 문장, Source는 기본 표에서 숨긴 기존 설정을 유지한다. 새 뉴스레터에는 공통 안내·심화 분석 영역을 넣지 않는다.
