# 쉬운 뉴스레터 작성 기준

planning-validation.md의 분석 품질 기준은 유지하되, 그 항목을 처음부터 모두 펼쳐 보여주지 않는다. 이 문서의 표시 순서를 우선한다.

## 3분 요약

- 기획 직무를 처음 준비하는 대학생이 이해할 수 있는 존댓말로 작성한다. 문장 하나에 핵심 하나를 담는다.
- 무슨 일이 있었나 → 왜 중요한가 → 사업기획이라면 → 상품기획이라면 → 어떤 데이터를 볼까 → 취업 활용 → 내가 해볼 것 순서로 읽힌다.
- 각 설명은 2~3문장. 데이터는 핵심 2개만 쉬운 뜻과 알고 싶은 점으로 설명한다. '내가 담당자라면'은 두 직무 설명에 녹여 반복을 줄인다.
- '기여이익', '반증', '재고·판촉 차이 통제' 등 상세 검증 용어는 접기 영역에 둔다. 필요한 전문용어는 사용한 자리에서 풀어 쓴다.
- 기업 의도·성과가 확인되지 않았다는 핵심 한계는 쉬운 요약에도 짧게 남긴다. 쉽게 쓰려고 불확실성을 없애거나 혜택을 과장하지 않는다.
- 작은 실습은 기본 20분, 산출물 하나와 질문 2~3개 정도로 제안한다. 사용자가 직접 적는 결과·생각·상태는 보존한다.

## 입력과 표시

schema_version 2의 각 분석 행에 `easy_read` 객체를 추가한다. 필드는 happened, importance, business, product, data, action, career, question의 8개 문자열이다. 전체 최대 1800자, 권장 900~1400자. 이 필드가 없는 과거 입력은 재현 목적으로 계속 지원하며 새 뉴스레터에는 반드시 넣는다.

planning.py는 쉬운 내용을 먼저 표시하고 기존 분석을 `<details>` 안에 보존한다. Notion에서 자식 블록은 탭으로 들여쓰기해야 실제 접기 영역에 들어간다. '내 생각', 실습 기록과 원문 출처는 접기 영역 밖에 유지한다.

기존 Notion 수정 시: 원문 본문·속성을 새 파일에 백업하고 분석 구간만 쉬운 요약 + 접힌 기존 분석으로 바꾼다. 기존 사용자 입력은 수정하지 않는다. Action 속성도 쉬운 실습과 일치시킨다. 본문 변경과 속성 변경은 각각 실행하고 재조회로 확인한다. Summary는 짧은 한 문장을 유지하며 Source는 기본 표에서 계속 숨긴다.
